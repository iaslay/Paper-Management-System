# 研读 · 论文看板

应用版本 0.4.0。已完成管理基础、阅读与记录、读后简介卡片，以及第四阶段“论文讨论与聊天生成卡片”。可使用现有 DeepSeek 讨论当前论文、继续追问、查看来源页，并把讨论整理成可编辑、可确认的新卡片版本。已有研究方向、中文速览、全页面连续阅读、笔记高亮和免密钥划词翻译继续可用。

## 运行

已在 Windows、Python 3.12、Node.js 24 环境验证。本机默认使用 SQLite，无需 Docker 或 Redis。论文管理、阅读、笔记与手工卡片无需模型密钥；AI 生成需要在应用的“模型设置”中配置服务。

在项目根目录打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

浏览器访问 [本机论文看板](http://127.0.0.1:8000)。首次运行请自己设置用户名、至少 12 个字符的密码及论文库名称；没有预设正式账号。按 Ctrl+C 停止服务，数据会保留。

从旧版升级：先等待阅读记录保存，在原服务终端按 Ctrl+C，再运行上述命令并刷新网页。脚本检查依赖及前端版本，缺少新增依赖时安装，版本变化时重新构建；服务启动后自动执行数据库迁移。本次交付已通过启动脚本构建并启动 8000 端口新版，刷新网页即可看到“论文讨论”入口。

在全新机器安装依赖，或依赖发生变化时：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Install
```

修改前端源码后重新构建：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Rebuild
```

`.env.example` 只提供配置参考，应用读取进程环境变量，不自动加载 `.env` 文件。默认服务只监听本机。数据库可通过 `PAPERBOARD_DATABASE_URL` 切换，但当前验收使用 SQLite；对外部署需额外配置 HTTPS、合法来源和安全会话。

## 已实现功能

- 单用户初始化、登录、退出、会话持久化、登录失败限流；密码使用 Argon2 摘要。
- 每批最多 20 份 PDF；逐文件上传反馈与重试；服务端检查 50 MiB、300 页、加密／损坏／空文件及空间容量。
- SHA-256 查重，同文件并发上传只产生一个论文记录；不同文件可分别保留。
- 获取 PDF 元数据标题与作者，支持人工修正标题、作者、年份和 DOI。
- 卡片、列表、三列阅读看板；通过选择框或拖动设置待读／阅读中／已读，支持收藏。
- PDF.js 原文预览、基础翻页与缩放；字体和字形映射在本地提供。文件接口登录保护并支持分段读取。
- 多研究方向；名称、别名、重命名、归档／恢复与合并；主题与普通标签分别管理。
- 批量添加／移除方向，逐论文报告成功、上限或冲突，支持重试未完成项。
- 标题、作者、方向名称和别名检索；任一／全部方向匹配；未分类、状态、年份、主题、标签、收藏筛选与去重分页。
- 论文回收站、恢复与彻底删除；过期回收站由服务启动及每小时检查清理。
- 编辑版本检查；登录过期后当前表单保留，重新登录可继续保存。

- 阅读页码、适应宽度／50%～300% 自定义缩放、旋转保存与恢复；最近阅读排序及继续阅读入口。
- PDF 内置目录、可见范围缩略图、当前原文的中文与英文文字搜索、搜索结果回跳；扫描页保留页码笔记。
- 同页多行高亮、四种颜色、摘录及关联评论；坐标绑定不可变原文，缩放与旋转后回显。
- 文字拖选松开鼠标后显示浮动操作，不挤动原文；图片底图中的隐藏文字层同样支持跨行拖选，拖到页边保留本页选区。
- 页码笔记、我的理解、待解决疑问与可能用途；独立保存、分页浏览、原文定位与删除确认。
- 停止输入 1 秒后保存，输入法组合保护，串行保存；请求回执防止重试重复创建。
- 保存失败保留页面内草稿，版本冲突比较，会话过期后继续保存；关闭、Esc、遮罩和退出共用离开检查。

- 模型设置：Responses、Claude Messages 或兼容视觉接口；服务地址、模型名称、密钥、输入模式、自动已读生成开关与用量上限。
- 两页无文字层的图片 PDF 能力测试；原生 PDF 优先，按页图片兼容，不使用独立 OCR；长文分批覆盖全部页序。
- 手动生成草稿，或显式开启首次标记已读触发；持久任务、进度、取消、有限重试、未知用量标识与预算预占。
- 结构化简介、研究问题、方法、贡献、结果、局限及人工填写的个人用途；原文事实、作者主张、系统推测和用户记录分别标记。
- 原页来源回跳、人工核对、手工建卡、不可变历史版本、编辑冲突比较和确认当前卡片；重新生成保留原卡片。
- AI 方向建议逐条采纳或忽略；已有名称与别名复用，新方向显式创建，采纳后参与现有方向检索。
- 论文信息页“AI 识别并填写”：标题、作者、年份、DOI 与三类分类建议；支持来源核对、未识别字段保留、等待时编辑保护、结果复用；保存时原子创建所选新分类。
- 每篇论文的多段讨论、持久问答、最近上下文追问、补充原文页、来源回跳、复制回答、停止生成与安全重试。
- 根据完整已完成讨论生成独立卡片草稿，直达草稿版本、编辑确认，并从卡片返回关联讨论；保留已有卡片和人工填写的个人用途。

上传、打开论文和保存普通笔记不会调用模型。划词翻译仅在点击“翻译”时发送选中文字，使用独立免密钥 Qwen 服务，不发送整份 PDF 或个人笔记。卡片默认关闭云端及自动已读生成；个人笔记默认不发送，生成前勾选才纳入。未保存的编辑只保留在当前页面，请等待保存完成或复制后再离开。卡片／笔记内容检索、Markdown 导出、完整备份恢复和创新思路仍在后续阶段。

## 使用 AI 填写论文信息

打开论文详情的“论文信息”，点击“AI 识别并填写”，等待结果填入表单后核对保存。研究方向、主题和普通标签建议可取消，新分类名称可以编辑，点击保存时才创建。阅读状态由用户维护，AI 不修改。

首版识别前四页和末页，最多五页；个人笔记不发送，没有独立 OCR。没有识别出的字段保持原值，等待期间的人工修改保留。点击“填入上次识别结果”复用成功结果，不产生新调用。详细规格和验收见[论文信息 AI 填写开发与验收](docs/论文信息AI填写开发与验收.md)。

## 使用 AI 卡片

1. 打开“模型设置”，选接口类型，填写 HTTPS 服务基础地址、模型名称和 API 密钥，开启云端模型。
2. 点击“保存并测试视觉能力”。测试只发合成文档，也会产生少量服务商用量；具体模型须具有视觉能力。
3. 打开论文详情的“简介卡片”，点击生成。需要纳入个人记录时，先在选择区勾选；默认只分析原文。
4. 查看来源页、编辑并保存新版本，最后确认当前卡片；方向推荐需要单独采纳。

自动模式在能力测试中优先原生 PDF，不支持时测试图片；实际生成固定使用已通过的模式。服务商格式与限制各异，兼容接口仍以测试结果为准。默认每批 12 页、请求 20 MiB、单任务 500,000 token、月度 2,000,000 token；视觉用量由模型决定，预占是估算，并非服务商账单的严格硬上限。正式首次使用建议先核对一篇较短论文。

0.3.0 首次交付通过了模拟模型的接口与故障验收；实际论文的摘要准确性尚未评估。测试数据中的“模拟验收”卡片不能作为论文结论。

0.3.1 修复了完整接口地址被重复追加路径的问题，并加入 DeepSeek 预设。DeepSeek 使用 `https://api.deepseek.com`、`deepseek-flash` 和按页图片输入；此 Responses 接口不接收 PDF 文件。已使用当前保存的密钥通过真实连接、两页合成图片识读和结构化卡片测试，共三次调用，用量写入应用；未发送用户论文，未向论文库保存测试卡片。实际论文的摘要质量仍需阅读核对。完整接口地址会自动规范为基础地址；修正同一接口的地址格式保留已有密钥，更换服务或协议仍需重新填写。

## 使用论文讨论

1. 打开论文详情的“论文讨论”，或在阅读工具栏点击“讨论”。沿用已有启用且测试通过的论文模型，当前为 `deepseek-flash`，无需再填密钥。
2. 开始或选择本篇讨论，输入问题后发送。默认补充上次阅读页，可改为最多 3 页或清空；扫描件请指定需要讨论的页。
3. 查看回答后继续追问，点击来源页核对原文。已发送内容保存在本机，未发送的问题在离开前提示处理，不会因关闭自动发送。
4. 点击“根据讨论生成卡片”，完成后“查看卡片草稿”；核对、编辑、保存并确认，确认后切换当前卡片。

模型会收到有限长度的论文文字、指定原文页、已有卡片的论文内容和聊天上下文；个人笔记与个人用途不自动发送。每次文字输入最多 40,000 字符、补充最多 3 页，界面显示实际覆盖与截断。回答结合最近最多 12 条已完成消息，卡片整理使用本段全部已完成问答。每段最多 50 条消息、60,000 字符；来源页合法不代表论断已被人工证实。详见[第四阶段实施方案](docs/第四阶段实施方案.md)和[开发与验收](docs/第四阶段开发与验收.md)。

## 数据与开发

```text
frontend/                 React 与 TypeScript 网页
backend/app/              FastAPI、业务规则与数据模型
backend/migrations/       Alembic 数据库迁移
backend/tests/            核心规则与 API 验证
data/paperboard.sqlite3   正式本机数据库
data/files/               私有原文，以文件哈希命名
data/.model-key           本机模型密钥的加密主密钥文件
docs/                     需求、开发和阶段验收记录
```

SQLite 的 WAL 与 SHM 文件属于数据库运行数据。正式备份功能实施前，手动复制数据目录应先停止服务，保留整个目录，包括数据库、原文与 `.model-key`。备份含私人论文、笔记和密钥密文，须按私有资料保管。Windows 主密钥由当前系统账号保护，迁移到其他账号或机器可能需要重新填写模型密钥；若使用 `PAPERBOARD_SECRET_KEY`，应单独保存该环境主密钥。

开发时分别启动两个终端：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

```powershell
cd frontend
npm.cmd run dev
```

开发页面位于 `http://127.0.0.1:5173`，API 由 Vite 转发；浏览器按需读取 PDF 字体资源，首次开发前执行一次 `npm.cmd run build` 准备资源。

运行后端验证：

```powershell
New-Item -ItemType Directory -Path .test-data -Force | Out-Null
cd backend
..\.venv\Scripts\python.exe -m pytest tests -q --basetemp ../.test-data/pytest
```

运行前端类型检查与构建：

```powershell
cd frontend
npm.cmd run build
```

运行前端自动验证：

```powershell
cd frontend
npm.cmd run test -- --run
```

历史验证：0.3.3 后端 119 项、前端 65 项；0.3.4 前端 69 项；0.3.5 前端 72 项；0.3.6 前端 86 项；0.3.7 后端 138 项、前端 92 项。本轮 0.4.0 后端 151 项、前端 101 项回归、TypeScript 与生产构建通过，真实 DeepSeek 问答和聊天生成卡片通过。正式库升级为 `0006_discussions`。本轮发布前完整备份在 `.test-data/discussion-before`，独立升级副本为 `.test-data/discussion-upgrade`；此前备份仍保留。恢复前先停止服务并另存当前目录，使用完整备份，避免覆盖之后的数据。

第三阶段浏览器验收空间位于 `.test-data/stage3-browser`；本轮使用独立 `.test-data/discussion-browser` 和真实 DeepSeek 配置验证，正式 `data` 未写入验收对话或卡片。启动脚本默认使用单个 API 进程，后台工作循环从 SQLite 领取任务；首版不要添加多个服务工作进程。
