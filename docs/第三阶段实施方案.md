# 第三阶段实施方案

版本 1.1｜2026-10-13｜M3：读后简介卡片，本机实现已交付

【本次更新】依据现有产品需求、开发方案和 M2 可信页面来源实现。继续采用本机单用户、SQLite、单 API 进程。无需独立 OCR、Redis 或 Docker。模型密钥由用户在设置中填写。

实现、测试结果和剩余质量验证见[第三阶段开发与验收](第三阶段开发与验收.md)。首次交付使用明确标记的模拟结果；0.3.1 已增加真实 DeepSeek 合成图片与结构化输出测试，实际论文质量仍需核对。

## 1. 交付流程

【0.3.2 更新】论文信息页也可调用视觉模型识别元数据与三类分类建议，结果填入可编辑表单，保存后生效；等待时的人工修改保留。任务用 `purpose=metadata` 复用现有表，来源和用量沿用现有规则；详见[论文信息 AI 填写开发与验收](论文信息AI填写开发与验收.md)。

配置模型并测试视觉输入 → 上传或打开论文 → 手动生成／首次标记已读触发 → 查看排队和生成阶段 → 核对卡片及来源页 → 编辑保存新版本 → 确认当前卡片 → 显式采纳研究方向推荐。

没有模型配置时，阅读与记录继续可用，并可手工创建卡片。个人笔记默认不发送，手动生成时可以明确勾选纳入的记录。已有卡片更新失败保留旧版本，刷新与打开详情不产生生成调用。

## 2. 数据与迁移

新增迁移 `0004_ai_cards`，前置 `0003_reading_records`。新增模型配置版本、生成任务、模型调用记录、卡片版本、论文卡片根记录及推荐决策表。`0005_task_order` 增加稳定队列序号，解决同秒创建任务的领取与显示顺序。原论文、账号、方向、笔记和高亮不改写。正式库迁移前保留在线数据库快照和原文件；开发与浏览器验收使用独立目录。

- 配置版本保存接口类型、地址、模型、输入模式、结构化输出选项、每批页数、输入字节限制、输出上限、调用上限及月度／单任务 token 上限；密钥以加密密文保存，不通过 API 回传。
- 任务保存原文哈希、配置版本、方向字典、用户明确选择的笔记快照、输入指纹、请求标识、状态、阶段、运行代次、租约、处理结果与预算预占。
- 卡片内容版本不可变，人工编辑创建新版本；确认采用卡片根记录的版本检查与当前版本指针。生成只添加草稿，已有当前卡片由用户确认后更新。
- 每版保留原生成模型、接口、输入模式、配置版本和提示版本；人工编辑继承原生成信息，不用当前设置冒充历史配置。
- 推荐决策按论文和规范化候选维护；采纳时核对现有分类、合并映射、数量上限与论文版本。新方向需要用户显式新建；忽略和已采纳候选显示其决策。

## 3. 模型与页面输入

通过服务端适配器支持 Responses、Claude Messages、兼容 Chat Completions 的视觉模型。接口地址必须为 HTTPS，禁止地址凭证、重定向及默认访问内网；测试专用本机接口仅由环境配置开启。没有访问权限或密钥时明确提示，不自动选择纯文本模型替代扫描件。

连接测试先发送不含论文的最小请求，再用本地合成的两页图片 PDF 验证输入；测试 PDF 没有文字层，两页分别显示不同标记。自动模式优先验证原生 PDF，必要时测试图片路径。任务在入队快照中固定已通过的输入模式，重新测试不会修改已排队输入。配置变更建立新版本。

PDF 按实际页序分批，超出请求字节限制继续拆小批次；图片通过隔离子进程渲染 JPEG，限制最长边与像素数。每个请求保存局部页序到 `page_sources` 的清单。模型只返回当前输入的局部页序，服务端还原原 PDF 的页序与页面标识；长文汇总只使用已校验的分段结果并再次核对引用。覆盖全部页面，不用抽样页冒充全篇分析。

## 4. 卡片结构与证据

结构版本为 `1.0`。简介最多 150 字符，研究问题 200，方法 400，贡献最多 3 项各 200，结果最多 3 项各 250，局限最多 3 项各 200；正文合计最多 2,000 字符。个人用途最多 80 字符，只由用户填写。论文类型为实证／理论／综述／其他／未确定。

正文各项包含文字、来源类型与证据列表。来源区分原文事实、作者主张、系统推测、用户记录。自动事实与作者主张必须有本篇输入中的页面来源；无法确认时填写缺失原因，不编造数值或领先结论。引用摘录属于模型识读，初始待核对。用户可逐条标记已核对；人工改写内容后相应引用重新待核对。笔记引用只能指向选中的用户记录，不能充当原文事实证明。

AI 推荐方向最多 5 项，优先使用字典中的标识，附理由及来源页。推荐校验失败只丢弃无效推荐并提示，不阻断有效正文保存。原文中的指令作为待分析内容处理，模型无外部工具执行能力。

## 5. 任务、重试与用量

状态为排队、运行、等待重试、成功、失败、取消，阶段包括准备、视觉理解、汇总、校验、保存。持久队列由本机后台工作循环领取；领取和写回使用运行代次检查，取消、删除论文和关闭云端后，晚到结果不能发布。

单请求默认 120 秒，任务运行上限 10 分钟。网络／限流／暂时服务错误受调用总数约束，最多两次额外尝试；格式与引用修复最多一次。调用前记录请求、页数和预占，调用后记录输入／输出 token 与服务请求标识。超时或响应未提供用量时明确记录未知，并按估算占用预算，不能记作零费用。进程恢复时，尚未开始调用的任务可重新领取；已经发出的未确认调用明确终结为结果不确定，需用户决定是否重试。

按原页数量、视觉输入估算、输出上限、长文汇总、重试及修复预占 token。单任务及月度上限在入队与调用前检查。首版只显示用量及预占，不在没有费率配置时展示虚假的货币费用。显式重新生成建立新任务；重复请求与相同输入使用已有任务或结果。自动已读生成默认关闭，由模型设置显式开启。

删除论文或清理任务后，当月已发出的调用用量继续占用预算。结束任务及其输入快照保留 30 天；无关联的历史月份调用记录到期清理，卡片版本保持。临时输入目录仅在具有系统标记、路径位于私有临时目录且超过一小时后清理。用量超过预估时提示，并按实际记录控制后续调用；预占不能保证服务商的严格账单上限。

## 6. API 与界面

- `GET/PUT /settings/model`：当前配置和安全更新；`POST /settings/model/test`：测试已保存配置；`GET /settings/model/usage`：月度预算及调用用量。
- `POST /papers/{id}/card-tasks`：手动生成，含请求标识、是否重新生成与明确选中的笔记标识；`GET /papers/{id}/card-tasks`、`GET /card-tasks/{id}`、`POST /card-tasks/{id}/cancel`：任务查询与取消。
- `GET /papers/{id}/card`：当前卡片、草稿、版本与决策；`POST /papers/{id}/card-versions`：手工建卡或基于版本编辑；`POST /card-versions/{id}/confirm`：确认；`POST /card-versions/{id}/direction-suggestions/{index}/accept|ignore`：采纳或忽略。

设置窗口包含模型配置、云端开关、首次已读自动生成、输入能力测试及用量。详情新增“简介卡片”页签，提供草稿／当前版本／历史、编辑与手工卡、来源回跳、推荐采纳。论文看板展示当前卡片简介与草稿／已确认状态。生成期间每两秒查询；离开或会话失效后停止查询。未保存的卡片编辑纳入统一离开检查。

## 7. 验收

自动测试覆盖配置版本与密钥遮蔽、地址检查、请求构造、真实 PDF 分批与页面渲染、引用越界及错篇、笔记默认不发送、正文与推荐独立校验、任务去重与预算、失败重试和取消、租约恢复与晚到结果、不可变版本、确认冲突、方向别名／合并／上限／忽略，以及旧库迁移。

浏览器用模拟 HTTP 模型完成配置、能力测试、生成、核对、编辑确认、历史版本、方向采纳和来源回跳；正文标明模拟验收，不能伪装成真实模型分析。真实云端质量与费用评估使用用户选定模型和密钥，单独记录；未实际调用时不能宣称真实论文事实准确率已验收。交付需通过前后端测试与生产构建，并记录当前限制及启动步骤。

## 8. 接口依据

Responses 的原生 PDF 输入与结构化输出依据 [OpenAI 文件输入](https://developers.openai.com/api/docs/guides/file-inputs)和[结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)。Claude PDF 输入依据[官方 PDF 支持说明](https://platform.claude.com/docs/en/build-with-claude/pdf-support)。隔离页面渲染依据 [pypdfium2 文档](https://pypdfium2.readthedocs.io/en/stable/python_api.html)；密钥加密使用 [Fernet](https://cryptography.io/en/stable/fernet/)。实际兼容性以配置后的能力测试为准。
